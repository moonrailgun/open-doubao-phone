# Open Doubao

Open Doubao 包含操作系统、桌面端和 Android 应用三个独立项目：

```text
os/        操作系统相关工程与镜像
desktop/   Tauri 桌面端
android/   Android 应用、Gradle 配置与 Wrapper
docs/      项目设计与开发文档
artifacts/ 本地打包与验证产物（不纳入版本控制）
output/    设计与实验输出
```

Android Studio 请直接打开 `android/`。各端的构建命令在对应目录执行。

## Android 应用

在 Android 手机上独立运行的任务助手：**无障碍元素优先，Jev 选择动作和判断效果，视觉模型负责规划、必要的页面理解与结果摘要**。任务循环和执行器都在手机内，运行时不需要电脑、ADB、root 或自建服务器。

当前为可安装的 `0.1.0` 开发版。支持打开应用、读取节点、点击、填写文字、滚动、坐标手势和返回；支持系统语音输入、自动执行、暂停后继续、紧急停止、加密配置和本地任务记录。开始任务后自动观察、操作和核对结果，需要手动处理时暂停，处理后可以继续原任务。

另有 `desktop/` 下的 Tauri 桌面端：同一局域网内通过扫码或设备码绑定手机，下发、停止和继续任务，修改手机的模型配置与应用范围，查看实时进度、回复、总结、历史记录与执行/访问日志。连接服务内置于桌面应用，无需部署服务器。

## 安装和配置

要求 Android 11/API 30 或更高，手机保持解锁且可以访问配置的 HTTPS 模型服务。

1. 安装 `artifacts/open-doubao-phone-0.1.0-lan-debug.apk`（包含桌面接收端；自行构建后位于 `android/app/build/outputs/apk/debug/app-debug.apk`）。这是开发签名的 APK，不是应用商店发行包。
2. 在底部齿轮图标（设置）页配置两个服务，然后点击「保存」：

   | 字段 | 内容 |
   | --- | --- |
   | Jev 接口 | 默认 `https://api.typesafe.ai/v1/systemone` |
   | Jev 模型 | 默认 `jev-latest`；也可以填服务支持的固定版本 |
   | Jev API Key | 对应 Jev 服务的密钥 |
   | Chat Completions 地址 | **完整** HTTPS 地址，例如服务提供的 `/v1/chat/completions` 接口 |
   | 模型标识/API Key | 该服务中支持文字和图片输入的模型及凭据 |
   | 总结语言 | 默认跟随系统；任务结束时的总结使用该语言 |

   Jev 接口必须接受 `model + state + questions`，返回 `answers` 中的 `choice`、`noul` 结果；不能直接填普通聊天接口。规划接口需支持 `messages`、`image_url`、`max_tokens` 和非流式 `choices[].message.content`。兼容网关的具体模型仍需实际验证。连接测试会分别发送一次请求，可能产生服务费用。
3. 回到机器人图标（任务）页，点击「开启无障碍服务」提示条，在系统设置中开启无障碍服务。侧载应用如遇受限设置，请按系统设置页面的提示允许；应用不会绕过系统权限。
4. 默认允许全部可启动应用；点击输入框右下角的网格图标（旁边数字为可用应用数）调整范围。打开「显示系统组件」或直接搜索名称、包名（例如 `gms`），可勾选 Google Play 服务等没有启动入口的组件，点击对勾保存。系统组件默认不授权；全选和取消选择只作用于当前显示的列表。至少选择一个应用，输入或说出任务（也可点示例快速填入），再点击输入框右下角的播放按钮开始任务。界面操作以 [Lucide](https://lucide.dev) 图标表示，每个图标都带有读屏名称。
5. 开始后由助手自动执行，应用内会显示当前步骤；屏幕边缘有可拖动的悬浮球，点开后显示当前步骤和「紧急停止」。超出应用范围或需要手动处理时，任务暂停并展开悬浮窗，处理后点击「继续」。任务执行期间屏幕保持常亮，不会自动息屏；暂停后恢复系统的自动息屏。继续会重新观察页面，保留原任务的计划、步骤和已读内容；仍超出范围时会再次暂停。
6. 在 Open Doubao 系统 v1.15 及以上，任务可以在虚拟屏上执行：应用在看不见的独立屏幕上打开和操作，期间手机可以照常使用。默认由模型在开始前快速判断（先问 Jev，Jev 不可用或拿不准时问 Chat 模型）：需要你亲眼看或亲手参与的任务（支付、登录验证、拍照扫码、通话、播放、要求展示给你看的）在前台执行，其余在虚拟屏执行；判断依据写在任务日志里。虚拟屏会话开着时，应用的任务页和悬浮球里都能实时看到画面（只能看，不能点）。需要手动处理时，在暂停的悬浮窗里点「转到前台处理」，应用会移到主屏幕，处理后点「继续」，剩余步骤改在前台执行。每个应用第一次在虚拟屏上运行时，系统会请你授权。在设置的「执行」页签可以改为固定虚拟屏或固定前台；其他系统只支持前台执行。
7. 无障碍服务开启后悬浮球常驻（锁屏时隐藏），开机或进程被回收后由系统自动恢复。展开后的悬浮窗可以从空白处拖动位置，按钮、输入框和结果滚动仍可正常使用。任务结束时悬浮窗自动展开显示总结，可直接在悬浮窗输入下一条命令继续执行，使用上次保存的应用范围和配置。

底部「记忆」页保存助手的长期记忆：每次任务都会把记忆和最近 3 条已完成任务（目标与结果）随规划、视觉和总结请求发给 Chat 模型，所以可以接着说「把刚才的结果记到备忘录」。说「记住……」或「忘掉……」时，助手只改记忆、直接回复，不操作手机；问「我车停哪了」这类记忆里已有答案的问题也直接回答。任务完成后助手会再调用一次模型，判断有没有值得长期记住的偏好或常用信息，结果写在该任务日志末尾。记忆最多 50 条、每条 200 字，可以在「记忆」页添加、点一条修改、删除或清空；屏幕上的文字不会被当作「记住」指令，提示词要求不记录密码、验证码等凭据，但请不要手动写入这类信息。记忆只存在本机加密文件中，不同步到桌面。

可从简单任务开始，例如搜索并摘要、修改一个普通应用选项、把文字填入备忘录草稿。三类任务的真机、真实模型结果见 [Android 真机验收记录](android/acceptance.md)。允许范围内的点击、输入、网址导航、坐标操作、读取、滚动和打开应用均自动执行。授权后的系统组件也可以操作，包括普通系统选项和选择已有账号；没有启动入口的组件需要由其他应用带出或手动进入，不能直接启动。发送、付款、删除、输入凭据和修改账号安全设置仍由模型交还手动处理；检测到密码输入框时本地直接暂停。手动处理后可继续，应用本地不做关键词拦截。

如果前台跳到未选应用（例如 Google Play 服务的登录/选账号页），助手立即暂停；该页面不会进入模型请求、截图或任务来源。请手动处理并返回已选应用后点击「继续」，无需重新创建任务。暂停期间不会自动操作或因等待超时结束，也不会自动扩大应用范围；随时可以点「紧急停止」。

即使应用已授权，无法读取页面、系统拒绝截图、无法打开目标、反复操作无进展或页面持续变化时，也会暂停并说明原因，等待手动处理后继续。授权不会绕过 Android 对受保护窗口和控件的限制。

为让用户选择没有桌面入口的组件，应用通过 `QUERY_ALL_PACKAGES` 枚举本机已安装应用；默认授权范围仍只有可启动应用，模型规划只接收本次已选包名。该权限的 Google Play 发行限制见 [官方说明](https://support.google.com/googleplay/android-developer/answer/10158779?hl=en)。

## 桌面端与手机绑定

本次构建产物：`artifacts/open-doubao-phone-desktop-0.1.0-macos-arm64.zip`（Apple Silicon Mac，解压得到 `.app`）和 `artifacts/open-doubao-phone-0.1.0-lan-debug.apk`。macOS 应用仅带本地临时签名，未做 Developer ID 签名或公证。

开发运行需要 Node.js 20.19+/22.12+、Rust stable，以及对应系统的 Tauri 构建环境（macOS 使用 Xcode Command Line Tools）。

```sh
cd desktop
npm ci
npm run desktop
```

1. 电脑和手机连接同一 Wi-Fi/局域网，在手机上安装本次构建的 `android/app/build/outputs/apk/debug/app-debug.apk`，完成模型配置与应用范围，并开启无障碍服务。
2. 桌面点击「绑定手机」，选择手机能访问的电脑局域网 IPv4 地址，点击「生成设备码」，显示绑定二维码和可复制的设备码。有 VPN 或多个网卡时应选择 Wi-Fi/有线网卡对应的地址。
3. 在手机设置的「桌面远程」页签中点击「扫码绑定」，允许相机权限后扫描桌面二维码，自动绑定并开启接收；也可以粘贴完整设备码，点击「绑定并开启接收」。扫码在手机本地处理，无需 Google Play 服务。二维码与设备码五分钟内有效，重新生成会使旧码失效；绑定成功后用于后续重连的凭据会保存。二维码和设备码包含授权凭据，请只交给自己的手机。
4. 桌面显示已连接后即可下发任务。手机需保持解锁，任务使用手机已保存的模型和应用范围；本地与桌面任务共用单任务限制，暂停中的任务也占用当前任务。可在桌面停止当前任务，或在手机悬浮球紧急停止；需要手动处理时，在手机上处理完再点击手机或桌面的「继续」（桌面继续同样要求手机已解锁）。
5. 桌面展示实时步骤、结果总结（与手机相同的 Markdown 子集，按纯文本渲染）和执行日志；窗口在后台时，任务暂停、完成、失败或停止会发送系统通知。历史记录从手机读取，最多 30 条，点击记录查看完整日志，也可以删除该记录；「访问日志」指已有的应用读取、动作、耗时与异常记录，不包含页面全文、截图档案或浏览器历史。
6. 侧边栏「模型配置」「应用范围」和「语音播报」直接读写手机上保存的设置。模型配置可先「测试连接」：由手机用表单中的值向两个服务各发一次请求，不保存，可能产生费用；已保存的 API Key 不会回传桌面，修改接口地址时需重新填写。应用范围与手机上的应用选择一致（可搜索、显示系统组件、全选当前列表）；新手机在桌面保存一次即可开始远程任务。语音播报同样不回传已保存的 Token，修改接口地址时需重新填写，清空接口地址即改用本地播报。任务执行或暂停时不能修改配置、应用范围或删除记录。

关闭手机「允许桌面下发任务」会断开连接；无障碍服务停用时接收端也会停止。重新开启接收或服务后自动重连。网络中断不会重复下发任务，也不会停止已经在手机执行的任务；响应超时后先查看手机或重连后的记录，避免手动重复执行。更换电脑 IP 后需要在两端解绑并重新生成设备码。当前一台桌面绑定一台手机，仅支持局域网 IPv4。

连接使用 WSS 与设备码中的 SHA-256 证书指纹校验。手机凭据保存在原有 Keystore 加密文件中，桌面凭据保存在应用数据目录（macOS/Linux 使用当前用户专属文件权限）；模型密钥不会同步到桌面。绑定并开启接收意味着该桌面可以下发任务并读取手机保留的全部任务记录。桌面解绑会撤销凭据并关闭连接；手机解绑会删除其本地凭据，再次配对前也需在桌面解除旧绑定。

如果不能连接，检查设备码有效期、手机接收开关、无障碍服务、所选网卡，以及电脑防火墙是否允许本应用接收 TCP `38687`。扫码时若未获得相机权限，可在系统设置中允许，或改用粘贴设备码。访客 Wi-Fi/AP 隔离可能禁止设备互访。普通 `npm run dev` 仅预览页面，必须运行 `npm run desktop` 才有手机连接能力。

构建桌面应用与运行验证：

```sh
cd desktop
npm run bundle                         # 当前系统的安装包
npm run bundle -- --bundles app         # macOS .app
npx playwright install chromium --only-shell
npm test                               # 无头浏览器，模拟原生桥接
npm run build
cd src-tauri
cargo test --locked --no-default-features
cargo check --locked
```

桌面核心测试包含真实 TLS/WebSocket 握手、认证、绑定持久化、请求响应、断线重连与解绑撤销；Android 测试覆盖设备码解析、命令范围、重复任务 ID、过期停止请求、真实 TLS 连接、证书不匹配时不发送凭据，以及关闭接收后丢弃迟到消息。浏览器测试会将生成的二维码解码，与完整设备码比对，并检查过期、关闭和重新生成时的清理行为。浏览器测试中的手机状态为模拟数据，不能代替真机联调。桌面连接模块已通过真实局域网 WSS 向实体手机下发任务、接收状态并读取记录（复用 `bridge` 模块与已保存绑定的无界面客户端），见 [Android 真机验收记录](android/acceptance.md)。尚未验证桌面窗口中的摄像头扫码配对、系统防火墙、厂商后台回收，以及 Windows/Linux 打包。桌面继续任务、应用范围、连接测试、删除记录和系统通知目前只经过模拟桥接、单元测试和编译检查，尚未与实体手机联调。

## 工作方式

```text
目标 → 规划模型（一次）→ 手机读取元素并构造完整动作候选
                          ↓
                  Jev：下一步 / 上一步效果 / 是否完成
                          ↓
             本地范围及页面检查 → 单个动作 → 新元素
                          ↓ 低置信度、无候选或执行无进展
                 规划/视觉模型 → 本地检查
                          ↓ 完成
                    基于观察的结果摘要
```

- Jev 从候选 ID 选择，不生成执行代码。候选包含规划阶段生成的待输入文字；新文字交给规划模型根据任务来源生成。最近 8 页保留完整节点，已读文字和视觉模型提取的事实另行保留，供跨应用草稿和最终摘要使用；来源累计达到 64,000 字符时结束任务，不淘汰早期来源。
- Jev 无法选择下一步且任务未完成时截屏，不以文字节点数量判断画面是否充分。Android 14 起使用目标窗口截图；Android 11–13 隐藏悬浮球并遮掉目标窗口之外的区域，有遮挡窗口时暂停任务。
- 执行前核对应用、窗口、方向、尺寸与节点快照；坐标动作在决策后和派发前还会核对截图，画面变化即丢弃旧操作。坐标仅限目标窗口，拒绝被其他窗口遮挡的区域。系统动作失败后重新观察，让视觉模型选择下一步，不直接重放失败动作。截图采用严格匹配，动画或滚动条淡出会使旧操作失效；连续六次决策期间画面变化时暂停任务。
- 每个任务最多 30 步、累计运行 5 分钟，暂停等待不计时；单次请求最多 60 秒。连续三次界面没有进展会调用视觉模型调整，六次仍无进展且不能确认完成时暂停；达到步数或时间上限仍会结束并说明原因。
- 紧急停止取消请求并使迟到响应失效。已经注入系统的手势无法撤回，但停止后不会派发新动作。进程重启不自动续跑任务；执行中或暂停时被回收的任务会在服务重新连接时标记为中断，崩溃时附带堆栈。
- 任务和所选应用的可访问文字会发给配置的服务；必要时还会发送截图。密钥、配置及最多 30 条任务记录使用 Android Keystore 加密存储，禁止备份；截图只在内存中处理。
- 每条任务记录附带执行日志：带毫秒时间戳的规划结果、每次页面读取、模型调用及耗时、动作与结果、超时所在的调用和异常堆栈；启动前检查未通过的任务也会留下记录。日志不含截图和屏幕全文，单条约 24,000 字以内，可在「记录」页展开查看和复制。

## Android 本地构建与验证

使用 JDK 17、Android SDK 36 和项目自带 Gradle wrapper。将 `sdk.dir` 写入本地 `android/local.properties`，不要提交该文件。从仓库根目录执行：

```sh
cd android
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
./gradlew :app:connectedDebugAndroidTest
```

设备测试请使用专用模拟器：测试会安装应用、开启它的无障碍服务、操作 debug 专用隔离页面。测试结束可以在系统设置里关闭服务。测试页面不包含在 release 构建中。

验证结果以本地测试报告为准：`android/app/build/reports/tests/` 与 `android/app/build/reports/lint-results-debug.html`（相对于仓库根目录）。

验证范围：核心单元测试覆盖 Jev 协议、动作边界、停止后迟到响应、页面变更、步数/时间上限、HTTP 取消、跨页来源保留与视觉事实进入摘要；Android 仪器测试覆盖真实节点、文字输入、点击、坐标手势、滚动、截图、安全窗口拒绝、全自动连续执行和悬浮球展开与紧急停止、Keystore 加密与损坏文件保留，并验证节点不变而像素变化时拒绝旧坐标。完整链路测试让 TaskController、CloudModels 协议解析和 AndroidPhone 实际执行共同运行，完成输入、保存和结果核对；HTTP 模型响应由测试提供，启动目标重定向到 debug 隔离页面。它们不代替真实云端推理；真机验收见下文。

真机验收在 Pixel 6 Pro（豆馅 OS v1.9，Android 17）上使用真实 Jev 与 Claude Opus 5.5 完成，结果、发现的问题与修复见 [Android 真机验收记录](android/acceptance.md)。尚未验证：Android 11–13 截图分支、拔线运行、跨应用任务在包含修复的镜像上的重测，以及真人语音唤醒。

## 源码入口

- `core/TaskController.kt`：单任务状态机、取消与自动恢复循环。
- `core/Protocol.kt`、`core/ActionPolicy.kt`：模型响应解析、动作候选与本地检查。
- `model/CloudModels.kt`：Jev 和 Chat Completions 客户端。
- `phone/AndroidPhone.kt`、`phone/AssistantService.kt`：Android 观察、执行和悬浮球。
- `data/Vault.kt`：加密配置与历史。
- `MainActivity.kt`：任务、配置、记录和语音输入。
- `remote/RemoteProtocol.kt`、`remote/RemoteReceiver.kt`：设备码、远程命令、证书固定与连接生命周期。

以上路径相对于 `android/app/src/main/java/com/moonrailgun/opendoubao/assistant/`。桌面页面位于 `desktop/src/`，内置连接服务位于 `desktop/src-tauri/src/bridge.rs`。详细方案见 [Android 设计文档](docs/superpowers/specs/2026-10-08-android-assistant-design.md) 和 [局域网桌面端设计](docs/superpowers/specs/2026-10-09-desktop-remote-design.md)。协议依据为 [TypeSafe Jev API](https://docs.typesafe.ai/api) 和 [Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。
