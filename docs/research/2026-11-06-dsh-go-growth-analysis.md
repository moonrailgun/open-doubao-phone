# DSH Go 为什么火了，Open Doubao 下一步该怎么做

研究日期：2026-11-06。GitHub 数据采于北京时间 00:48，B 站搜索页采于 00:54；其他页面为本次检索时可读取的版本。本文讨论公开传播与试用入口，不把关注量当作活跃用户。

配套文件：[30 天执行方案与发布素材](2026-11-06-open-doubao-launch-playbook.md) · [数据快照与口径](2026-11-06-growth-evidence.json)。

## 1. 先回答问题

**DSH Go 更像一个已有热门工具终于推出了手机入口；Open Doubao 则在让用户理解一种新的手机使用方式。两者的获客起点不同。** DSH Go 承接 DeepSeek Harness / dsh-TUI 的使用需求；Open Doubao 首发强调操作系统，而最容易试用的独立 Android 应用没有被清楚地交到用户手里。

目前最有把握的判断是：**Open Doubao 同时存在受众定位偏宽、安装入口断裂的问题。还没有证据说明，它因手机操作能力不如 DSH Go 而失败。** 没有同设备、同任务、同模型的对照实验，也没有两边的安装、激活与留存数据，不能从 Star 数倒推产品质量。

最值得复现的路径是：找到一个已有需求的人群 → 提供可以立即安装的产品 → 展示他们能照做的任务 → 让评测者独立复现 → 持续修复首次使用障碍。最不值得照搬的是：为了追热点继续堆功能，或者把换吉祥物、求 Star 当作主因。

## 4. DSH 做对了什么，哪些判断最可靠

| 判断 | 证据与机制 | 置信度 / 不能推出什么 |
| --- | --- | --- |
| 从已有用户的需求切入 | TUI 已有积累；Go 的名称、介绍与远程能力直接连接 DSH 生态 | 高：存在生态基础。中：它贡献了多少新增用户，无法量化 |
| 一句话就能让目标用户理解 | 历史 README 把手机本机运行、连接电脑放在显著位置 | 中高：降低理解成本；不代表普通消费者同样需要 |
| 公测时就可以下载和上手 | v1.0.0 README 已提供 Releases / 下载站、指南、社区入口；目前下载页同时提供全球与 GitHub 路径 | 高：入口存在。没有网络条件一致的下载速度实测 |
| 给别人可展示、可讨论的东西 | 首发版本已有角色形象和对话分享；公测窗口有短片和长测评 | 中：有利于传播。不能证明吉祥物或分享卡单独带来增长 |

## 5. Open Doubao 最该修的是哪里

### 5.1 首发故事让安装门槛看起来比实际更高

Linux.do 与 V2EX 首发都以手机操作系统为主标题。Linux.do 列表先写 Android 17 系统，再写独立 App 和桌面端。**读者可能因此预期要刷机或换设备，这是推断，不是已测得的认知比例。** 当前 README 已把独立 App 解释得更清楚，不能把首发问题描述成所有现有页面都没改过。[Linux.do 原帖](https://linux.do/t/topic/3048127)、[V2EX 原帖](https://www.v2ex.com/t/1249919)、[当前 README 快照](https://github.com/moonrailgun/open-doubao-phone/blob/f55ee82a9d94caa17606e8314db40951673b4c5c/README.md)。

更直接的证据是：首发当天至少两条回复在找下载或要求 APK。第一条下载反馈发生于北京时间 11:08，首个带 APK 的 Release 到 23:56 才发布。它证明当时存在试用意愿和阻碍，不能证明因此损失了多少用户。[帖子回复](https://linux.do/t/topic/3048127)、[v1.0.1 Release](https://github.com/moonrailgun/open-doubao-phone/releases/tag/v1.0.1)。

### 5.2 现在 APK 已有，入口仍然断着

本地核验基线：`f55ee82a9d94caa17606e8314db40951673b4c5c`；官网同时读取了线上 HTML。

| 触点 | 现状 | 新用户受到的影响 | 最小修复 |
| --- | --- | --- | --- |
| 官网“开始体验” | 跳转 GitHub README，没有直接 APK 下载按钮 | 已决定试用后仍需寻找下一步 | 主按钮到当前 Android APK，次按钮到安装指南 |
| README“开始探索” | 仍说“当前为开发版，可从源码构建体验” | 误以为必须搭开发环境 | 首屏和安装段给 Release；源码构建留给开发者 |
| 安装指南 | 写 0.1.0，指向不纳入 Git 的本地 `artifacts/...debug.apk` | 外部读者无法按步骤取得这个文件 | 改成公开发行包与手机安装步骤，版本说明同步 |
| 仓库 About | description 为空，topics 为空，homepage 为旧 vercel 地址 | 搜索结果与转发预览缺少解释 | 补一句产品描述、少量准确标签、当前域名 |
| 使用条件 | 模型配置、无障碍授权等与实现细节混在长指南里 | 新手难判断自己能否成功 | 独立列出 Android 版本、模型需求、权限、第一项任务 |

来源：[官网](https://open-doubao.moonrailgun.com/)、[网站源码快照](https://github.com/moonrailgun/open-doubao-phone/blob/f55ee82a9d94caa17606e8314db40951673b4c5c/website/index.html)、[指南快照](https://github.com/moonrailgun/open-doubao-phone/blob/f55ee82a9d94caa17606e8314db40951673b4c5c/docs/guide.md)、[仓库元数据 API](https://api.github.com/repos/moonrailgun/open-doubao-phone)。这些是可核实的转化障碍；About 缺失本身不足以解释 340 倍差距。

### 5.3 产品展示已经有基础，缺少的是别人复现的证据

现有演示包含 4 个应用、21 步，并诚实标明一次人工继续，也提供实时录像。已有角色形象和产品网站。因此“没有视频”“缺个可爱形象”不是准确诊断。下一步要补的是：**陌生用户按公开指南，能否用发行包在自己的普通手机上完成一项任务。** 当前演示使用 Pixel 6 Pro；本次没有重新安装发行包，也未证明其他厂商设备与演示环境等价。[README 演示说明](https://github.com/moonrailgun/open-doubao-phone/blob/f55ee82a9d94caa17606e8314db40951673b4c5c/README.md)。

### 5.4 “同类产品”只成立一部分

| 用户要做的事 | DSH Go | Open Doubao 当前公开能力 |
| --- | --- | --- |
| 离开电脑后，接着使用电脑上的 Agent | 核心叙事和能力之一 | 当前桌面工作台不是这个方向 |
| 在电脑上给手机下任务、查看执行 | 不据本次资料作全面判断 | 已有局域网桌面工作台 |
| 让手机操作应用完成任务 | 有手机控制能力 | 核心定位 |
| 定制手机操作系统与系统入口 | 不是本次比较的主要卖点 | 豆馅 OS，当前适配范围有限 |

来源：[DSH Go README](https://github.com/ccch1mneyyy/dsh-Go)、[Open Doubao README](https://github.com/moonrailgun/open-doubao-phone)。两边都写了“手机”和“Agent”，不意味着同一用户会把它们当作二选一。

## 6. 建议选择哪条路

| 路线 | 初始人群与价值 | 取舍 |
| --- | --- | --- |
| **优先：普通 Android 上的任务助手** | 已有视觉模型 Key、愿意开无障碍权限的 Android / AI 爱好者；把当前页面或跨应用信息整理成可检查的结果 | 复用已有能力，最快验证；仍需证明比手动操作有实际价值 |
| 第二阶段：成为其他 Agent 的手机执行工具 | DSH 等生态用户，希望电脑上的 Agent 调用手机能力 | 最接近 DSH 的生态获客路径，但接入协议、授权、返回结果尚未验证；不能宣传已经支持 |
| 独立分支：豆馅 OS | 有适配设备、愿意刷机的系统爱好者 | 深度和差异化较强，受众更窄；使用独立入口和验收标准 |

首轮不要同时向三类人讲三套故事。先把普通 Android App 的安装与第一项任务做通；桌面端、虚拟屏和 OS 作为有明确需要时的后续入口。Android 14+ 的普通手机虚拟屏仍有 Shizuku / ADB + scrcpy 等条件，不能混成“所有手机装上就能后台执行”。

**推荐首个验证场景**：让助手阅读测试用户已经打开的公开文章，滚动获取必要内容，再在任务结果里给出三条可核对的摘要。它不需要发消息、支付或额外账号；但页面能否读取、摘要是否正确、是否比用户现有方法省事都必须实测。后续再测试跨应用整理笔记；已有复杂演示继续作为能力上限展示。

如果用户反馈“直接复制给聊天工具就够了”，不要用成功率掩盖价值不足：转向他们反复遇到的跨应用任务。**技术跑通和值得反复使用是两个不同的验收。**

## 7. 可以复现什么，不能保证什么

| 可以执行和验收 | 不能靠计划保证 |
| --- | --- |
| 清晰的人群与一句话承诺 | DeepSeek 当期的注意力规模 |
| 公开 APK、简短指南、可核对的第一项任务 | 作者既有 TUI 社区和信誉的即时复制 |
| 短演示 + 实时原片 + 可复现评测资料 | 官方人士推荐、榜单席位、媒体自发报道 |
| 小样本安装观察、问题修复、主动重复使用记录 | 相同速度获得一万 Stars |
| 基于真实需求的生态合作与集成实验 | 下载人数必然转化成长期用户 |

对应行动、文案、邀请草稿、指标表头和停止规则已写入[执行方案](2026-11-06-open-doubao-launch-playbook.md)。建议下一笔投入放在安装与首次成功，再决定扩大发布；不要先把目标定成“追平 DSH 的 Star 数”。

## 8. 研究范围与尚缺的证据

本次检索覆盖 GitHub、官网、科技媒体、Linux.do、V2EX、B 站、知乎热榜存档、X 的索引提及和应用收录站；针对公众号、掘金的检索没有得到足够可靠、可归属的新增原始资料。这是跨渠道公开研究，无法穷尽全网、私域群聊、推荐流和已删除内容。

优先采用原始仓库、发行资源、历史标签与原帖；转载不重复计数。B 站视频 API 未成功读取，播放数来自同一次搜索 HTML；知乎与 X 原页访问受限，因此只作为扩散线索。没有访问双方私人分析后台，没有估算刷量比例、买量金额、收入或媒体合作费用；没有证据时不作指控。

要把本报告的解释升级为因果判断，还需要三组数据：Open 的渠道访问→安装→首次成功；用户是否误认为需要刷机；同类实际任务的首次成功与 7 日复用。配套方案用人工观察先补这些数据，不要求先造一套埋点系统。

本次产物为研究与发布准备材料，未修改产品页面、未发布内容、未联系作者或媒体、未创建 Git commit，也未进行真机对比实验。
