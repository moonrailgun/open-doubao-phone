# 豆馅 OS v1 实施计划

归档日期：2026-10-09。本文保存本次会话形成的方案及 Claude Code 交叉审查结论；归档不代表已经实现、构建或完成真机验收。

## 目标与方案

基于 Pixel 6 Pro 当前已验证启动的 AOSP 17，制作可重复构建的定制镜像，实现系统常驻助手、应用 Logo 开机动画，以及三个固定唤醒词。

已与 **Claude Code** 完成交叉审查，并纳入默认助手设置、后台录音验证、崩溃恢复和镜像处理方面的修正。

按已确认的选择：

- 整个助手 App 常驻，正式版本随系统镜像更新。
- 每次开机首次解锁后自动监听，支持息屏、锁屏唤醒。
- 唤醒、语音识别和播报全部本地运行；任务推理继续使用现有云端模型。
- 首版提供单轮任务与停止、继续指令；播报期间暂停监听。

## 系统集成

- 将现有 `com.moonrailgun.opendoubao.assistant` 内置为 `persistent` 系统应用，加入省电豁免。清除最近任务不会停止助手；进程异常退出后由系统恢复，但不会自动重放未完成任务。
- 首次设置引导用户选择默认数字助手、授权麦克风并启用无障碍。默认助手通过系统设置页选择；AOSP 的助手角色不支持普通角色申请弹窗。[AOSP 角色定义](https://android.googlesource.com/platform/packages/modules/Permission/+/refs/heads/main/PermissionController/res/xml/roles.xml)
- 保留现有桌面。助手组件不启用 Direct Boot，首次解锁前不访问凭据或启动语音。
- 使用一个前台服务管理录音与播放，显示监听状态和关闭入口；监听期间持有必要的 CPU 唤醒锁。麦克风隐私开关、通话或录音冲突发生时暂停，条件恢复后重新监听。
- 增加语音引擎初始化失败保护：检测到上次初始化异常中断时暂停自动启动，让用户仍能进入设置处理。
- 使用现有 Logo 制作黑底居中的开机动画，安装到 `/system/media/bootanimation.zip`；保持 Bootloader 解锁提示。

## 语音链路与接口

| 环节 | 方案 |
|---|---|
| 唤醒 | `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01` |
| 固定词 | “豆馅你好”“你好豆馅”“豆馅同志”，用官方工具生成并校验关键词 tokens |
| 识别 | SenseVoice int8 `2024-07-17`，配合 Silero VAD |
| 播报 | `kokoro-int8-multi-lang-v1_1`，复用上游 Android TTS 引擎 |

- 实现真实的 `VoiceInteractionService`、会话服务和 `RecognitionService`。助手内部保持单进程，所有入口共用一个录音实例；同时只允许一个识别请求。
- 现有麦克风按钮改用本地识别，继续只填写任务输入框；唤醒入口识别完成后调用现有任务执行器。
- “停止／停止任务”终止当前任务；“继续／继续任务”仅恢复已有暂停任务。忙碌时拒绝新任务，不建立隐式队列。
- 将启动和继续的锁屏检查放到共用入口，复用已有逐操作安全检查。锁屏唤醒只提示“请先解锁”，解锁后重新下达指令；保留现有应用授权和人工确认机制。
- TTS 引擎使用独立 APK；助手通过文件描述符请求合成，完成后由自己的前台服务取得音频焦点并播放，以适配 Android 17 后台音频限制。[Android 17 音频规则](https://developer.android.com/about/versions/17/changes/bg-audio)
- 播报复用现有 Markdown 纯文本解析，最多读前 300 字，超出提示查看全文。锁屏或取消时停止播报并清理临时音频。
- 分别保存模型与依赖许可证：SenseVoice 权重使用 FunASR 条款，Kokoro 权重使用 Apache-2.0，TTS 原生依赖涉及 GPL；助手侧关闭 TTS 原生编译，不将整条链路统称为 Apache-2.0。

## 实施与镜像交付

1. **离线语音闭环**：先用普通 APK 验证本地识别、独立 TTS 引擎和现有输入按钮。
2. **系统助手行为**：加入唤醒、任务指令、前台服务、状态恢复与首次设置；验证重启解锁后无需打开 App 即可录音。
3. **系统常驻集成**：使用同一签名，将高于开发版版本号的 APK 内置进镜像，验证应用数据和 Keystore 保留。
4. **品牌动画**：独立完成 Logo 动画及启动验证。

各部分按可独立验证、回退的原子提交交付，不夹带其他未跟踪项目文件。

原始镜像保持不变，定制配方放在 `os/custom/`。在 Linux 构建环境中修改镜像副本，保留文件权限、SELinux 标签和 capabilities。当前镜像已确认包含 `shared_blocks` 和 AVB footer，必须先处理共享块，再重建与最终尺寸一致的 AVB 元数据。

构建前预留至少 40 GB 工作空间；最终检查必须计入共享块展开、模型和文件系统开销，确认没有超过 `super` 容量。沿用已验证的刷写路径，后续升级默认不清数据，保留上一份可启动镜像。

## 验收与风险

- 自动检查覆盖关键词配置、录音互斥、取消与迟到回调、锁屏限制、崩溃保护，以及现有单元测试、Lint 和 APK 构建。
- 真机验证三词在亮屏、锁屏和深度待机下的唤醒；覆盖重启首次解锁、清除最近任务、进程异常退出、通话和麦克风隐私切换。
- 初始唤醒目标：安静环境 1 米距离，每词至少成功 18/20 次；8 小时混合环境音误唤醒不超过 2 次。记录唤醒、识别和首次播报延迟。
- 对比开启与关闭监听的 8 小时息屏耗电；验证离线识别与播报、无网络任务错误提示，以及不清数据升级后的配置和凭据。
- 默认助手绑定、后台录音、镜像启动和数据保留全部通过，才认定正式镜像可交付。

本轮仅完成设计与交叉审查，尚未实现或真机验证语音、耗电。CPU 全天监听会增加耗电；系统常驻提供回收保护和自动恢复，不能保证永不崩溃，正式更新需要替换镜像。

## 附录：Claude Code 交叉审查记录

审查日期：2026-10-09。审查以仓库代码阅读、提供的 AOSP 源码与官方文档为依据，同时包含审查者尚未独立复核的平台行为判断。以下是结论摘要与最终处理方式，不是全部通过的验收报告。

| 审查项 | 纳入方案的处理方式 | 剩余验证 |
|---|---|---|
| 默认数字助手 | 实现真实的 VIS、会话服务与识别服务；通过系统设置选择，不使用普通 `ROLE_ASSISTANT` 申请弹窗，不新增 RRO | 确认 `dumpsys voiceinteraction` 正常绑定，角色持有者为助手包 |
| 重启后的后台录音 | 先用普通 APK 和手动助手选择验证首次解锁后自动录音；检测录音被系统静音，而不是将其当作安静环境 | 无需打开 App 时，麦克风前台服务可启动，录音 App-op 允许，录音未被静音 |
| 常驻与初始化恢复 | 助手单进程、不启用 Direct Boot；一个前台服务管理 microphone 与 mediaPlayback；原生引擎初始化前后设置和清除标记 | 首次解锁前的生命周期、初始化崩溃后的恢复入口、停止监听后释放资源 |
| 镜像更新与数据 | 开发 APK 与系统 APK 使用同一签名，正式版本号高于开发版；不通过卸载开发 APK 迁移，不清数据刷写 | 包替换后 UID、配置、应用数据与 Keystore 解密能力保留 |
| 权限与省电 | 按实际请求配置权限；使用运行时麦克风授权、前台服务、唤醒锁和省电豁免；不引入 `CAPTURE_AUDIO_HOTWORD` 或 `HotwordDetectionService` | 仅对实际需要的 privileged 权限配置 allowlist；无多余权限或启动错误 |
| 锁屏与任务接口 | 在共用启动和继续入口检查锁屏；复用 `AndroidPhone.unlocked()` 的逐操作检查和现有息屏处理 | UI、远程、语音入口一致；锁屏不展示任务结果、不执行自动化；“继续”不恢复已终止任务 |
| 本地 TTS 与识别互斥 | 复用上游独立 TTS 引擎，显式绑定，通过可寻址的缓存文件描述符合成，完成后由助手播放；识别忙碌返回 `ERROR_RECOGNIZER_BUSY` | 音频焦点、迟到回调、临时文件清理；助手原生库关闭 TTS 后无 eSpeak 依赖；各模型许可和分发材料齐全 |
| 镜像修改与容量 | 修改副本并保留 xattrs；处理共享块与 AVB；保留原有 `product`；检查开机动画覆盖优先级 | 文件系统一致性、SELinux 标签、真实分区尺寸、成功启动和无 AVC 拒绝 |

### 审查意见中保留的边界

- 审查者曾按约 550 MB 新增内容与约 988 MB `super` 余量推测容量足够。最终方案没有接受这一推测作为结论：共享块展开和文件系统开销仍可能增加空间需求，必须以构建结果计算。
- 审查者提出唤醒提示延迟 p50 不超过 700 ms、5 秒以内语句在端点后 1.5 秒内返回识别结果。这两项尚无 Pixel 6 Pro 实测，最终方案仅要求记录延迟，不将其列为已承诺指标。
- 不清数据更新、助手角色保持、后台录音豁免和进程恢复均需要目标系统实测；源码和文档判断不能替代真机验收。
- 归档时没有下载或编译语音模型，没有安装新的助手 APK，也没有修改或刷写定制系统镜像。
