# Open Doubao 使用与开发指南

[← 返回项目介绍](../README.md)

本文保留安装、配置、运行机制与开发验证的详细说明。命令与代码路径默认相对于仓库根目录。

Open Doubao 包含操作系统、桌面端和 Android 应用三个独立项目：

```text
os/        操作系统相关工程与镜像
desktop/   Tauri 桌面端
android/   Android 应用、Gradle 配置与 Wrapper
docs/      项目设计与开发文档
artifacts/ 本地打包与验证产物（不纳入版本控制）
output/    设计与实验输出
```

Android Studio 请直接打开 `android/`。各端的构建命令在对应目录执行。

## Android 应用

在 Android 手机上独立运行的任务助手：**无障碍元素优先，Jev 选择动作和判断效果，视觉模型负责规划、必要的页面理解与结果摘要**。任务循环和执行器都在手机内，运行时不需要电脑、ADB、root 或自建服务器。

当前为可安装的 `0.1.0` 开发版。支持打开应用、读取节点、点击、填写文字、在搜索框提交、滚动、坐标手势和返回；支持系统语音输入、自动执行、暂停后继续、停止、加密配置和本地任务记录。开始任务后自动观察、操作和核对结果，需要你同意或手动处理时暂停，点继续即授权并接着执行原任务。

另有 `desktop/` 下的 Tauri 桌面端：同一局域网内通过扫码或设备码绑定手机，下发、停止和继续任务，修改手机的模型配置与应用范围，查看实时进度、回复、总结、历史记录与执行/访问日志。连接服务内置于桌面应用，无需部署服务器。

## 安装和配置

要求 Android 11/API 30 或更高，手机保持解锁且可以访问配置的 HTTPS 模型服务。

1. 安装 `artifacts/open-doubao-phone-0.1.0-lan-debug.apk`（包含桌面接收端；自行构建后位于 `android/app/build/outputs/apk/debug/app-debug.apk`）。这是开发签名的 APK，不是应用商店发行包。
2. 在底部齿轮图标（设置）页配置规划与视觉服务（Jev 可选），然后点击「保存」：

   | 字段 | 内容 |
   | --- | --- |
   | Jev 接口 | 默认 `https://api.typesafe.ai/v1/systemone` |
   | Jev 模型 | 默认 `jev-latest`；也可以填服务支持的固定版本 |
   | Jev API Key | 可选，留空停用 Jev |
   | Chat Completions 地址 | **完整** HTTPS 地址，例如服务提供的 `/v1/chat/completions` 接口 |
   | 模型标识/API Key | 该服务中支持文字和图片输入的模型及凭据 |
   | 总结语言 | 默认跟随系统；任务结束时的总结使用该语言 |

   Jev 接口必须接受 `model + state + questions`，返回 `answers` 中的 `choice`、`noul` 结果；不能直接填普通聊天接口。规划接口需支持 `messages`、`image_url`、`max_tokens` 和 `choices[].message.content`；视觉步骤以流式请求，读 `choices[].delta.content`，动作一到就执行，服务忽略流式时按普通响应处理。兼容网关的具体模型仍需实际验证。连接测试会向已配置的服务各发送一次请求，可能产生服务费用。
   **Jev 多模态（实验）**：手机设置 → 模型或桌面模型配置中打开并保存，下一次任务生效；默认关闭，关闭时保留原流程。开启后优先由 Jev 看截图，直接选择目标应用、下一步动作和判断完成，并用 Box 定位无文字节点的按钮。Jev 无法确定可信动作或目标位置时，把当前截图交给通用视觉模型决定这一步，下一步再交回 Jev；视觉模型也可按原流程确认完成或请求人工处理。编写输入文字、记忆编辑和组织最终答案仍使用文字模型。接口失败或响应格式无效会报错，不触发此回退。

   Jev 的置信度门槛统一为：普通模式 ≥ 0.7，实验模式 ≥ 0.6。执行与只读使用相同门槛，覆盖动作选择、完成判断、意图和应用选择，以及实验模式的回答核验、目标存在与坐标可信度；不再单独判断只读类别。

   需要支持图片与 Box 的 Jev 1.14：原生接口可填 `jev-1.14.0`，OpenRouter 可用 `https://openrouter.ai/api/v1/systemone` 和 `~typesafe/jev-latest`，分别使用对应服务的 Key；不会自动修改已有地址或模型。参见 [TypeSafe 图片协议](https://docs.typesafe.ai/images)、[Box](https://docs.typesafe.ai/primitives/box) 与 [OpenRouter 多模态协议](https://openrouter.ai/docs/guides/community/multimodal-decisions)。Jev 的结构化接口不会直接转写图片文字；视觉回退可将读到的内容保留为后续回答素材。Jev 使用节点滚动，视觉回退仍可使用原有坐标动作。“测试连接”只验证基本接口连通，不证明多模态模型可用。

3. 回到机器人图标（任务）页，点击「开启无障碍服务」提示条，在系统设置中开启无障碍服务。侧载应用如遇受限设置，请按系统设置页面的提示允许；应用不会绕过系统权限。
4. 默认允许助手操作所有应用和系统组件（设置的搜索页、Google 登录与选账号页等没有启动入口的组件也包括在内），助手自身除外。点击输入框右下角的网格图标（有排除时旁边显示排除数），勾选不让助手操作的应用；打开「显示系统组件」或直接搜索名称、包名（例如 `gms`），也可以排除没有启动入口的组件，点击对勾保存。排除当前列表和取消排除只作用于当前显示的列表，至少要留一个应用。规划可以从能直接打开的应用或当前所在应用开始。输入或说出任务（也可点示例快速填入），再点击输入框右下角的播放按钮开始任务。界面操作以 [Lucide](https://lucide.dev) 图标表示，每个图标都带有读屏名称。
5. 开始后由助手自动执行，应用内会显示当前步骤；屏幕边缘有可拖动的悬浮球，点开后显示当前步骤和「停止」。遇到付款、删除，以及指令里没写明发给谁、发什么的发送时，先暂停征求同意，点击「继续」即授权它执行该操作；指令里写明了对象和内容的消息（如「给 Demo User 发个你好」）直接发送，屏幕上的对象或内容和指令不一致时仍会暂停；超出应用范围或需要手动处理（如输入密码）时同样暂停，处理后点击「继续」。找不到下一步、动作被本地检查拒绝或页面暂时无法读取时自动重试，连续 3 次失败才暂停；同一页面上的同一操作做过 2 次仍没有进展时也会暂停。任务执行期间屏幕保持常亮，不会自动息屏；暂停后恢复系统的自动息屏。继续会重新观察页面，保留原任务的计划、步骤和已读内容；仍超出范围时会再次暂停。
   打开某个应用、回桌面、返回、打开蓝牙或 WLAN 等设置页、查电量或存储空间这类明确指令走快速通道：在手机上直接完成，不调用模型、不写总结，结果是一句固定的话（如「已打开飞书」「电量 80%」）。
   开始任务时先读取允许范围内、没有密码输入框的当前页面：应用、页面文字交给意图判断和规划，截图交给规划与回复。能在当前页完成的任务直接继续，不重新打开应用，也不切到虚拟屏；「当前文章说了什么」可直接根据可见内容回复，需要阅读全文则规划滚动阅读。配置 Jev 时，用 Jev 快速判断聊天还是任务（最多 3 秒），规划同时开始。纯聊天直接根据当前前台页面的文字和截图回复，不规划步骤或操作手机；即使设置为虚拟屏执行，聊天仍读取前台。未配置 Jev、判断失败或不确定时走任务流程，由规划模型选择直接回答页面问题或继续操作。聊天同样遵守应用排除范围和密码页面保护。

6. 在 Open Doubao 系统 v1.15 及以上，任务可以在虚拟屏上执行：应用在看不见的独立屏幕上打开和操作，期间手机可以照常使用。默认由模型在开始前快速判断（配置了 Jev 时只问 Jev，3 秒内没答复按前台；未配置 Jev 时问 Chat 模型）：只有单纯查询信息、不需要给你展示的任务（查天气、读取或总结内容、查看某个数值或状态）在虚拟屏执行，其余（打开应用或页面、展示或播放、发送、支付、登录、改设置、编辑或起草）都在前台执行；拿不准、两项概率相同或判断失败时按前台执行。判断依据写在任务日志里。虚拟屏会话开着时，应用的任务页和悬浮球里都能实时看到画面（只能看，不能点）。需要手动处理时，在暂停的悬浮窗里点「转到前台处理」，应用会移到主屏幕，处理后点「继续」，剩余步骤改在前台执行。应用要打开本次任务以外的页面（例如设置的搜索页属于另一个应用）时，自动转到前台继续执行。每个应用第一次在虚拟屏上运行时，系统会请你授权。在设置的「执行」页签可以改为固定虚拟屏或固定前台；其他系统只支持前台执行。设置页底部的「调试」打开调试页：试播内置提示音、测试播报、模拟唤醒与识别自检（只显示文字不执行）、试算执行方式判断，查看运行状态和最近的语音事件。
7. 在 Open Doubao 系统上，等待唤醒词和录指令都以系统的热词通道录音，状态栏不显示麦克风指示点，录指令时由助手的「正在听」卡片提示。助手同时是无障碍服务，系统的音频策略不允许这样的助手在后台用普通音源录指令（会被静音），所以录指令也走热词通道；其他应用调用本机语音识别时仍用普通音源，指示点照常显示。长按电源键让助手开始听指令；关机和重启菜单要同时按电源键和音量上键，或者从快捷设置里的电源按钮进入。系统自带的「双击电源键打开相机」已关闭，双击电源键不做任何事。无障碍服务开启后悬浮球常驻（锁屏时隐藏），开机或进程被回收后由系统自动恢复。展开后的悬浮窗可以从空白处拖动位置，按钮、输入框和结果滚动仍可正常使用。任务结束时悬浮窗自动展开显示总结，可直接在悬浮窗输入下一条命令继续执行，使用上次保存的应用范围和配置。

底部「记忆」页保存助手的长期记忆：每次任务都会把记忆和最近 3 条已完成任务（目标与结果）随规划、视觉和总结请求发给 Chat 模型，所以可以接着说「把刚才的结果记到备忘录」。说「记住……」或「忘掉……」时，助手只改记忆、直接回复，不操作手机；问「我车停哪了」这类记忆里已有答案的问题也直接回答。任务完成后助手会再调用一次模型，判断有没有值得长期记住的偏好或常用信息，结果写在该任务日志末尾。记忆最多 50 条、每条 200 字，可以在「记忆」页添加、点一条修改、删除或清空；屏幕上的文字不会被当作「记住」指令，提示词要求不记录密码、验证码等凭据，但请不要手动写入这类信息。记忆只存在本机加密文件中，不同步到桌面。

可从简单任务开始，例如搜索并摘要、修改一个普通应用选项、把文字填入备忘录草稿。三类任务的真机、真实模型结果见 [Android 真机验收记录](../android/acceptance.md)。允许范围内的点击、输入、网址导航、坐标操作、读取、滚动和打开应用均自动执行。填完文字后的“提交”（相当于按键盘上的搜索键）只在搜索框和地址栏里执行，按输入框的资源名和描述判断；聊天框里回车就是发送，本地直接拒绝，只能点发送按钮。系统组件默认也可以操作，包括普通系统选项、设置的搜索页和选择已有账号；没有启动入口的组件需要由其他应用带出或手动进入，不能直接启动。权限授权弹窗、应用安装与卸载确认、虚拟屏授权框固定不让助手操作，遇到时暂停交给你。发送、付款、删除、输入凭据和修改账号安全设置仍由模型交还手动处理；检测到密码输入框时本地直接暂停。手动处理后可继续，应用本地不做关键词拦截。

如果前台跳到被排除的应用，助手立即暂停；该页面不会进入模型请求、截图或任务来源。请手动处理后点击「继续」，无需重新创建任务。暂停期间不会自动操作或因等待超时结束，也不会自动扩大应用范围；随时可以点「停止」。

即使应用已授权，无法读取页面、系统拒绝截图、无法打开目标、反复操作无进展或页面持续变化时，也会暂停并说明原因，等待手动处理后继续。授权不会绕过 Android 对受保护窗口和控件的限制。

应用通过 `QUERY_ALL_PACKAGES` 枚举本机已安装应用，以便默认允许、也可以排除没有桌面入口的组件；模型规划接收允许范围内能直接打开的应用，以及当前所在应用。该权限的 Google Play 发行限制见 [官方说明](https://support.google.com/googleplay/android-developer/answer/10158779?hl=en)。

## 桌面端与手机绑定

在仓库根目录运行 `./release.sh`（或 `./release.sh patch|minor|major|X.Y.Z`），会同步更新 Android 与桌面安装包版本并创建 GitHub Release。发布后 CI 分别构建并上传 APK、macOS Apple Silicon / Intel 的 `.dmg`、Windows x64 的 `.exe` 安装包，以及 Linux x64 的 `.deb` 和 `.AppImage`。需要等对应构建任务完成，Release 附件才会出现。macOS 应用仅带临时签名，未做 Developer ID 签名或公证；Windows 安装包未配置代码签名。

Android 普通安装版和桌面端启动时会检查 GitHub 最新正式 Release，也可在手机「设置」底部或桌面侧栏点击「检查更新」。发现新版后可查看更新说明，并用浏览器下载对应系统和架构的安装包，再手动打开安装。启动检查失败不会弹窗；手动检查会显示错误并允许重试。Android 系统版随系统镜像更新，不使用普通 APK 覆盖。

开发运行需要 Node.js 20.19+/22.12+、Rust stable，以及对应系统的 Tauri 构建环境（macOS 使用 Xcode Command Line Tools）。

```sh
cd desktop
npm ci
npm run desktop
```

1. 电脑和手机连接同一 Wi-Fi/局域网，在手机上安装对应版本的 APK，完成模型配置与应用范围，并开启无障碍服务。
2. 桌面点击「绑定手机」，选择手机能访问的电脑局域网 IPv4 地址，点击「生成设备码」，显示绑定二维码和可复制的设备码。有 VPN 或多个网卡时应选择 Wi-Fi/有线网卡对应的地址。
3. 在手机设置的「桌面远程」页签中点击「扫码绑定」，允许相机权限后扫描桌面二维码，自动绑定并开启接收；也可以粘贴完整设备码，点击「绑定并开启接收」。扫码在手机本地处理，无需 Google Play 服务。二维码与设备码五分钟内有效，重新生成会使旧码失效；绑定成功后用于后续重连的凭据会保存。二维码和设备码包含授权凭据，请只交给自己的手机。
4. 桌面显示已连接后即可下发任务。手机需保持解锁，任务使用手机已保存的模型和应用范围；本地与桌面任务共用单任务限制，暂停中的任务也占用当前任务。可在桌面停止当前任务，或在手机悬浮球停止；需要手动处理时，在手机上处理完再点击手机或桌面的「继续」（桌面继续同样要求手机已解锁）。
5. 桌面展示实时步骤、结果总结（与手机相同的 Markdown 子集，按纯文本渲染）和执行日志；窗口在后台时，任务暂停、完成、失败或停止会发送系统通知。历史记录从手机读取，最多 30 条，点击记录查看完整日志，也可以删除该记录，或点「下载模型调用记录」把这条任务完整的模型请求与响应（含截图）打包下载到电脑的「下载」文件夹，交给 AI 排查（手机按 150 KiB 分块传输）；「访问日志」指已有的应用读取、动作、耗时与异常记录，不包含页面全文、截图档案或浏览器历史。
6. 侧边栏「模型配置」「应用范围」和「语音播报」直接读写手机上保存的设置。模型配置可先「测试连接」：由手机用表单中的值向已配置的服务各发一次请求，不保存，可能产生费用；已保存的 API Key 不会回传桌面，修改接口地址时需重新填写。应用范围在桌面上以允许的应用显示（可搜索、显示系统组件、全选当前列表），默认全部勾选，取消勾选即排除，保存后手机存的是被排除的应用；新手机不保存也能开始远程任务。语音播报同样不回传已保存的 Token，修改接口地址时需重新填写，清空接口地址即改用本地播报。任务执行或暂停时不能修改配置、应用范围或删除记录。

关闭手机「允许桌面下发任务」会断开连接；无障碍服务停用时接收端也会停止。重新开启接收或服务后自动重连。网络中断不会重复下发任务，也不会停止已经在手机执行的任务；响应超时后先查看手机或重连后的记录，避免手动重复执行。更换电脑 IP 后需要在两端解绑并重新生成设备码。当前一台桌面绑定一台手机，仅支持局域网 IPv4。

连接使用 WSS 与设备码中的 SHA-256 证书指纹校验。手机凭据保存在原有 Keystore 加密文件中，桌面凭据保存在应用数据目录（macOS/Linux 使用当前用户专属文件权限）；模型密钥不会同步到桌面。绑定并开启接收意味着该桌面可以下发任务并读取手机保留的全部任务记录。桌面解绑会撤销凭据并关闭连接；手机解绑会删除其本地凭据，再次配对前也需在桌面解除旧绑定。

如果不能连接，检查设备码有效期、手机接收开关、无障碍服务、所选网卡，以及电脑防火墙是否允许本应用接收 TCP `38687`。扫码时若未获得相机权限，可在系统设置中允许，或改用粘贴设备码。访客 Wi-Fi/AP 隔离可能禁止设备互访。普通 `npm run dev` 仅预览页面，必须运行 `npm run desktop` 才有手机连接能力。

构建桌面应用与运行验证：

```sh
cd desktop
npm run bundle                         # 当前系统的安装包
npm run bundle -- --bundles app         # macOS .app
npx playwright install chromium --only-shell
npm test                               # 无头浏览器，模拟原生桥接
npm run build
cd src-tauri
cargo test --locked --no-default-features
cargo check --locked
```

桌面核心测试包含真实 TLS/WebSocket 握手、认证、绑定持久化、请求响应、断线重连与解绑撤销；Android 测试覆盖设备码解析、命令范围、重复任务 ID、过期停止请求、真实 TLS 连接、证书不匹配时不发送凭据，以及关闭接收后丢弃迟到消息。浏览器测试会将生成的二维码解码，与完整设备码比对，并检查过期、关闭和重新生成时的清理行为。浏览器测试中的手机状态为模拟数据，不能代替真机联调。桌面连接模块已通过真实局域网 WSS 向实体手机下发任务、接收状态并读取记录（复用 `bridge` 模块与已保存绑定的无界面客户端），见 [Android 真机验收记录](../android/acceptance.md)。尚未验证桌面窗口中的摄像头扫码配对、系统防火墙、厂商后台回收，以及 Windows/Linux 打包。桌面继续任务、应用范围、连接测试、删除记录和系统通知目前只经过模拟桥接、单元测试和编译检查，尚未与实体手机联调。

## 工作方式

```text
目标 → 规划模型（一次）→ 手机读取元素并构造完整动作候选
                          ↓
                  Jev：下一步 / 上一步效果 / 是否完成
                          ↓
             本地范围及页面检查 → 单个动作 → 新元素
                          ↓ 低置信度、无候选或执行无进展
                 规划/视觉模型 → 本地检查
                          ↓ 完成
                    基于观察的结果摘要
```

- Jev 从候选 ID 选择，不生成执行代码。候选包含规划阶段生成的待输入文字；新文字交给规划模型根据任务来源生成。最近 8 页保留完整节点，已读文字和视觉模型提取的事实另行保留，供跨应用草稿和最终摘要使用；来源累计达到 64,000 字符时结束任务，不淘汰早期来源。
- Jev 无法选择下一步且任务未完成时截屏，不以文字节点数量判断画面是否充分。Android 14 起使用目标窗口截图；Android 11–13 隐藏悬浮球并遮掉目标窗口之外的区域，有遮挡窗口时暂停任务。
- 执行前核对应用、窗口、方向、尺寸与节点快照；坐标动作在决策后和派发前还会核对截图，画面变化即丢弃旧操作。坐标仅限目标窗口，拒绝被其他窗口遮挡的区域。系统动作失败后重新观察，让视觉模型选择下一步，不直接重放失败动作。截图采用严格匹配，动画或滚动条淡出会使旧操作失效；连续六次决策期间画面变化时暂停任务。
- 每个任务最多 30 步、累计运行 5 分钟，暂停等待不计时；单次请求最多 60 秒。连续三次界面没有进展会调用视觉模型调整，六次仍无进展且不能确认完成时暂停；达到步数或时间上限仍会结束并说明原因。
- 停止会取消请求并使迟到响应失效。已经注入系统的手势无法撤回，但停止后不会派发新动作。进程重启不自动续跑任务；执行中或暂停时被回收的任务会在服务重新连接时标记为中断，崩溃时附带堆栈。
- 任务和所选应用的可访问文字会发给配置的服务；必要时还会发送截图。密钥、配置及最多 30 条任务记录使用 Android Keystore 加密存储，禁止备份；模型请求中的截图也会随调试记录加密保存。
- 每条任务记录附带执行日志：带毫秒时间戳的规划结果、每次页面读取、模型调用及耗时、动作与结果、超时所在的调用和异常堆栈；启动前检查未通过的任务也会留下记录。这份执行摘要不含截图和屏幕全文，单条约 24,000 字以内，可在「记录」页展开查看和复制。
- 新任务另外保存完整模型调试记录：执行方式判断、规划、Jev 决策、视觉调用及重试、总结、记忆更新和语音改写的请求 JSON 与原始响应正文，附任务/调用 ID、阶段、时间、耗时、HTTP 状态及请求 ID。请求在发送前落盘，失败或取消也会记录；进程被杀时可能只有请求文件。记录包含提示词、屏幕文字和发送的截图，不受执行摘要长度限制；响应仍受原有 1 MiB 安全上限约束，超限或读取中断会标记 `truncated`。API Key 和接口查询参数值脱敏，不保存 Authorization。
- 调试记录在本机压缩后用 Keystore 加密，随任务删除或超过最近 30 条时清理。手机「记录」中展开任务，点击「导出模型调试记录」可保存 ZIP，含 `task.json` 和 `calls/<调用ID>.request.json` / `.response.json`；按事件 `time` 排序查看，正文在 `body` 字段。ZIP 为明文并可能包含个人数据与截图，请仅分享给可信的人。旧任务无法补录；连接测试与 TTS 音频不在任务调试记录内，桌面仍只读取执行摘要。

固定语音提示的文案和音频位于 `android/app/src/main/assets/voice/prompts/`。`prompts.json` 同时供生成脚本和播放匹配使用：唤醒、重听、停止、解锁及固定任务状态/错误提示直接播放内置 WAV，无需网络或实时合成；动态结果、含具体应用或错误详情的提示仍走 TTS。设置页试听始终用于验证当前配置的 TTS 音色。修改固定文案时，用 `TTS_TOKEN=... python3 android/tools/make_voice_prompts.py <TTS 接口地址>` 生成缺失片段；需要重录已有片段时加 `--overwrite`。音频统一为单声道 PCM16、24 kHz。

## 源码入口

- `core/TaskController.kt`：单任务状态机、取消与自动恢复循环。
- `core/Protocol.kt`、`core/ActionPolicy.kt`：模型响应解析、动作候选与本地检查。
- `model/CloudModels.kt`：Jev 和 Chat Completions 客户端。
- `phone/AndroidPhone.kt`、`phone/AssistantService.kt`：Android 观察、执行和悬浮球。
- `data/Vault.kt`：加密配置与历史。
- `MainActivity.kt`：任务、配置、记录和语音输入。
- `remote/RemoteProtocol.kt`、`remote/RemoteReceiver.kt`：设备码、远程命令、证书固定与连接生命周期。

以上路径相对于 `android/app/src/main/java/com/moonrailgun/opendoubao/assistant/`。桌面页面位于 `desktop/src/`，内置连接服务位于 `desktop/src-tauri/src/bridge.rs`。详细方案见 [Android 设计文档](superpowers/specs/2026-10-08-android-assistant-design.md) 和 [局域网桌面端设计](superpowers/specs/2026-10-09-desktop-remote-design.md)。协议依据为 [TypeSafe Jev API](https://docs.typesafe.ai/api) 和 [Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。
